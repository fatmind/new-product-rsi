# 选品自迭代实验 · 该怎么改进（讨论共识汇总）

> 一句话：这个 RSI 实验做不上去，不是 Reward 定义不清，是归因不清——链条太长，一个带噪声的破零数字没法分摊回每一步决策。改进的方向不是把环境做得更逼真，而是**切短归因链，让每一段都能当场验证、当场裁分支**。

---

## 一、现在的处境（报告自己暴露的）

跑了 5 轮（r1–r5），自迭代确实在真复盘、有证伪有修正，但结果卡住：

- 破零品数五轮一直是 1~2 个，没有真提升；r4 的 50% 破零率是数字游戏（下发从 4 个缩到 2 个，破零品数没变）。
- 自己定的止损规则自己不执行（r4 判 kids 别再推，r5 又推了）。
- 评卷失败连续两轮没进复盘，反而是学习盲区。
- 小簇噪声大（kids 期望 3 单、实际 4/2/1），被读成价格信号。

**核心卡点：整个环境学不动，原因是"归因难"，不是"Reward 定义难"。**

## 二、Reward 定义不难，归因才难

- **Reward 定义本来是清楚的**：破零 = 7 日过 5 单，无歧义；环境也稳定可复现。但它还是学不动。
- **真正难的是信用分配（归因）**：最终只有一个"破零/没破零"信号，它由一整条链共同造成：
  ```
  选了哪个簇 → 补贴多少 → 商家定什么价 → 随机波动 → 破零
  ```
- 链条越长，单拿一步出来和最终结果的因果越稀薄——分不清是选品错、补贴少、商家乱定价还是纯粹运气差。kids 降价销量反而掉，不是降价没用，是归因归错了。

**稳定环境救不了 Reward**：环境稳定解决"可复现"，Reward 可学解决"可归因"，两个正交。仿真稳定到能随便重放，照样学不动——证明"可复现"补不上"可归因"的窟窿。

## 三、别再把责任推给"它是模拟的"

- **逼真度上 team3 碾压选品**（team3 是真环境，选品是建模），这点成立。
- 但逼真度决定的是"这个改进点在真实世界值多少钱"，**不决定"改进点能不能被找出来、被信"**。
- 反而选品握着一个 team3 永远没有的东西：**完全可控 + 可重放 + 上帝视角真值表**——只是没在"学习"环节用它，光在"展示"环节用（alerts 拿来给人看）。

结论：选品学不动，不是输在"假"，是输在**明明假得完全由自己定义，却没把这层定义权拿去缩短归因链**。

## 四、破局：切短归因链 = DFS 剪枝

把长链切成一段段，每段之间插一个**便宜、独立、当场能判**的检查点。每到一个节点，用一个便宜的判据把它当场裁掉：

| 段 | 检查点（当场能判） | 裁掉的分支 |
|---|---|---|
| 选簇 | 商家定 12.9，是我引导的封顶内吗？ | 引导措辞问题（→ 直接给死目标价） |
| 定价 | 实付压进竞对带了吗？ | 价格问题（大部分时候裁掉） |
| 成交 | 价格都对还卖不动？ | 需求/转化问题（剩下的重点攻这个） |

- 裁掉"价格"分支 → 注意力（模型弹性）全压到没被裁的"需求/用户群匹配"上。
- 这比倒推整条链省在哪：**每一层的判据便宜、独立、当场给定，不用等全局结果。**

### 关键坑：裁据是"代理指标"，不是证明

"进竞对带" ≠ "价格全对"，它只是"价格没离谱"的代理。kids 进带了还卖不动，你可能裁掉价格、把锅推给需求——但真凶也许在更上游（不该选 kids 这个簇）。**所以切短不是保证裁对，是保证每一刀都有据可查、可单独复核**，把"长链猜不出凶手"变成"每层一个可复核的裁据，裁到只剩窄空间再下重手"。

## 五、分段责任 vs 全局目标

全局目标（破零 / 真需求 / 真转化）不变，但**被分派到各节点各守一段**：

- 定价段守"价带内"，需求段守"用户群匹配"，商家段守"言行一致"。
- 每一段都不是全部答案，每一段只负责"这个变量是不是凶手，裁一裁"。
- DFS 能收敛，不是每层都裁对，是每层裁据便宜到能把树搜完——剩的窄空间才轮到用贵且全局的判断（需求匹配、用户群）去攻。

## 六、具体落地清单

1. **把 alerts 变成学习信号，不是展示**：report 里已有现成材料（r2 商家定 4.99 超引导、r5 皮具厂前后矛盾、r3 降价赶客的噪声告警）——每条 alert 已是一个切好的短段、一个浮出的改进点，接回复盘当参考，而不是只给人看。
2. **三段切短各配一个可复核判据**：
   - 定价格：给定死目标价 + 留商家上浮余量，别用"封顶"措辞；
   - 商家格：跨轮言行要一致，矛盾即告警；
   - 成交格：价格没问题 → 才怀疑需求匹配。
3. **归因让模型分层**：先用便宜判据裁掉能裁的，别再对着整条链乱猜"降价赶客"这种伪结论。
4. **把可控性打出来**：同一簇多轮取平均、重放抹掉那 1 单的随机噪声——"可重放"是你比 team3 强的地方，别浪费。
5. **补一条从 log 提炼"改进点语言"的通道**：team3 靠协议让 agent 主动写偏离（experience/decision），loop_002 就是这么产出的高信号密度改进点。选品要补的是"让每一轮的 log 也沉淀成改进点，而不是一个破零分数"。

## 七、和 team3 机制的对照

选品和 team3 是**同一种动物**：都能从执行 log 里提炼"可定位、可验证的改进点"。

- team3（真 + 不可控）：改进点来自真实环境的偏离，高信号密度，但失败不可复现、不可控。
- 选品（假 + 可控）：改进点来自仿真，但能重放、能抹噪声、能看见真值表——两个维度各赢一头。

**终局判断**：只要归因链短到"这一段的决策 → 这段的可见结果"在仿真里也扎实成立，逼真度有 gap 也能照常迭代、照常长出改进点——到那时选品和 team3 就在同一起跑线上，只是 team3 打的是"真"，选品打的是"归因得清"。

## 八、一句话

RSI 的难，难在归因；破解归因的唯一办法，是主动把链子切短——让每一段都能单独验证、当场裁分支，把"乱猜整条链"变成"一颗一颗裁，裁到只剩真难点再下重手"。
